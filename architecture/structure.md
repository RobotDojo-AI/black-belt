# Robot Dojo Repository Structure

This file is the human-readable placement contract for the repo. It explains where things belong so humans and agents can build without adding random surfaces.

The enforceable source for root placement is `config/root-allowlist.lock.json`. `scripts/check-root-lock.js`, `scripts/gate.js`, `config/structure.json`, and `architecture/surfaces.json` enforce it. Architecture allowlists are human-authored protected surfaces. Local commits require a non-repo owner approval record; GitHub merges require CODEOWNERS review and the root-lock workflow.

## Root files

Root files must be rare.

| File | Purpose |
| --- | --- |
| `ACCOUNT_RECOVERY.txt` | Local operator account recovery instructions |
| `README.md` | Public repository overview |
| `CLAUDE.md` | Claude Code adapter only |
| `.gitignore` | Repo-wide ignore policy |
| `.vercelignore` | Vercel deploy exclusion policy |
| `identity.example.json` | Example local identity config |
| `index.js` | Local server entry point |
| `middleware.js` | Vercel edge middleware |
| `install.sh` | Terminal install path |
| `knip.json` | Dead-code/dependency analysis config |
| `package.json` | Node project manifest |
| `package-lock.json` | npm lockfile |
| `playwright.config.js` | Playwright test config |
| `skills-lock.json` | Installed skill/plugin lockfile |
| `stryker.config.mjs` | Mutation testing config |
| `vercel.json` | Vercel deployment config |
| `LICENSE` | License |

`ACCOUNT_RECOVERY.txt` stays at root because emergency recovery must be discoverable when the operator is locked out or disoriented. It is not part of the architecture doc set.

Do not add new root docs. Cross-cutting product and repo docs belong in `architecture/`.

| `gateway/` | Sole canonical gateway folder: Hono control plane, Redis integration, Terraform deploy source, deploy scripts, device registration, tunnel routes, and blind TCP/SNI relay code | App business logic, filled Terraform vars/state/plans |
| `lib/` | Core reusable business logic | Route handlers, frontend, one-off scripts |
| `quarantine/` | Temporary holding zone for misplaced files, gitignored | Permanent storage |
| `routes/` | Hono route handlers | Reusable business logic |
| `scripts/` | Operational, QA, migration, and generator scripts | Library modules |
| `tests/` | Automated tests and fixtures | Product source |

Recoverability rule: every file must be in exactly one recoverability class — GitHub-tracked source, GCP-backed private/local state, or explicitly regenerable tool output. `scripts/check-backup-recoverability.js` enforces this for ignored files so GitHub and GCP stay MECE instead of relying on memory.

## Doc-class homes

Canonical docs distill signal. Each doc class has exactly one home. Generated docs follow code and config; curated docs guide future code.

| Doc class | Home | Notes |
| --- | --- | --- |
| Product truth | `architecture/product.md` | Customer promise, launch scope, tier model |
| System shape | `architecture/architecture.md` | Human-readable architecture; internal "chat is the hero" framing |
| Placement rules | `config/root-allowlist.lock.json` → `architecture/structure.md` | This file derives from the lock |
| File inventory | `architecture/sitemap.md` | Generated by `scripts/generate-sitemap.js` |
| Directory ontology | `architecture/ontology.md` | Generated by `scripts/generate-ontology.js` from the lock |
| Agent OS roster + routing | `agents/agents.md` | Per-agent bodies in `agents/personas/{Name}.md` |
| Build conventions | `agents/build-conventions.md` | Portable cross-tool engineering rules |
| Quality contract | `agents/default-quality.md` | Embedded by include marker into every persona and skill |
| Skills (build + tool) | `agents/skills/*/SKILL.md` | Each skill carries its own contract + steps |
| Current work state | `user/workbenches/topics/work/robot-dojo/wk_robot_dojo/kanban.md` | Not auto-loaded globally |
| Owner user context (chat) | `user/workbenches/user/wk_user/context.md` | Chat-injected distillation, ≤ `USER_CARD_CHAR_BUDGET` |
| Owner user context (IDE deep) | `user/workbenches/user/wk_user/USER.md` | Long-form deep companion |
| Owner writing (voice + structure + formatting) | `user/workbenches/user/wk_user/user-voice/` (`voice.md`, `structure/`, `formatting/`, `samples/`, `check.md`, auto `learned.md`) | How the owner writes to the world (PII) — gitignored, never shipped. Compounds from writing samples and sent mail. Operator chat is not a source. |
| Miyagi writing (voice + structure + formatting) | `config/agent-voice/` (`voice.md`, `structure/`, `formatting/`) | How Miyagi talks to the owner — PII-free, included by every persona. Chat logs and working-together feedback train this path via standing corrections. |
| Topic context (canonical) | `user/contexts/topics/{t1}/[{t2}/]context.md` | Compact memory for chat |
| Entity context (canonical) | `user/contexts/{people,companies,places}/{display-slug}--{stable-id-suffix}/context.md` | Display-slug name; stable entity id in frontmatter and DB |
| Workbench resume + substrate | `user/workbenches/{topics|entities}/.../{workbench_id}/INDEX.md` + `substrate/` | Deep work; promotes durable truth into the attached `context.md` |
| Pipeline story artifacts | `user/workbenches/topics/work/robot-dojo/wk_robot_dojo/stories/{id}/` | Per `STORY_SCHEMA.json` |

**Package rule.** Canonical topic and entity memory lives inside a package directory as `context.md`. Topic package names use topic slugs. Entity package names use a human-readable display slug plus a stable ID suffix: `{display-slug}--{stable-id-suffix}`. The package directory is also the owner for workbenches and other first-class context-local support files attached to that owner.

**Context-doc ontology.** Every `context.md` (user, topic, or entity) is loaded directly into chat — it is the compact canonical memory layer, not deep substrate. Section schema: a `# Topic|Entity: {slug}` heading, a short "what this covers" paragraph, optional boot-up reading list, then current state. Injection contract: `wk_user/context.md` is injected by `lib/identity-card.js` (budget `USER_CARD_CHAR_BUDGET = 4000`); topic and entity `context.md` files are loaded by the topic/entity resolver. Compact ≠ thin: every line earns its place because it ships in every chat turn for that selection.

**Workbench placement.** Deep topic/entity work belongs in a registered workbench under `user/workbenches/`, not hidden inside a pipeline story or nested inside compact context packages. The canonical resume index lives at `user/workbenches/topics/{t1}/{t2}/{workbench_id}/INDEX.md` or `user/workbenches/entities/{people|companies|places}/{entity-package}/{workbench_id}/INDEX.md`. Pipeline artifacts are not deleted, but pipeline remains process history rather than the workbench home.

Placement rule: if it is evidence, cite it. If it is thinking, move it. If it is truth, promote it. Raw evidence can remain in `user/transcripts/`, `user/databases/`, `user/files/`, or another approved user source root; `docs/` is evidence only when the documentation itself is the source. Derived research, analysis, dashboards, normalized datasets, decisions, todos, and next-action state belong in the attached workbench. Long-form workbench synthesis may be as deep as the work requires; durable compressed conclusions promote into the attached topic/entity `context.md`.

Every workbench `INDEX.md` includes a distillation contract. The contract names the purpose, canonical target, compact-context rule, long-synthesis home, RAG substrate, and review threshold. Agents must state or refresh that contract before major research or build work so the user can correct the promotion boundary before work accumulates.

Every T1 and T2 topic has a natural default workbench landing zone. Creating a topic creates that default workbench unless one already exists. Entity workbenches are created on demand when a person, company, or place becomes the owner of deep work. Topic rename, delete, or merge operations must consolidate attached workbenches by rehoming their `INDEX.md` and substrate under the surviving topic/entity and repointing canonical promotion targets.

`user/contexts/research/` is retired. It is not an approved destination for new or canonical workbench substrate; if it reappears, the contents must be moved into `user/workbenches/` or cited from an approved source root.

Every workbench attaches to one or more canonical targets:

- topic: T1 or T2 topic slug
- person: canonical person ID
- company: canonical company ID
- place: canonical place ID

`thing` and health-condition entities are not workbench attachment types. Health investigations attach to the existing personal health topic. Durable findings promote back into the attached topic/entity context and RAG; the workbench keeps the in-flight layer resumable.

## Enforcing gates

Pre-commit gates fire on every commit. Each one targets a specific class of failure.

| Gate | Script | Failure it blocks |
| --- | --- | --- |
| Root allowlist | `scripts/check-root-lock.js` | New top-level entries not approved in `config/root-allowlist.lock.json` |
| Registry schema | `scripts/check-registry-schema.js` | Malformed entries in `architecture/surfaces.json` |
| Canonical mode | `scripts/check-canonical-mode.js` | Re-introduction of autonomous doc-writer pattern |
| Doc budget | `scripts/check-doc-budget.js` | Any registered surface over its `max_chars` cap |
| Human-authored class | `scripts/gate-human-authored.js` | Staged edits to a human-authored canonical surface without a story declaring it in `meta.json.touches` |
| Canonical readers | `scripts/check-canonical-readers.js` | Skill or persona missing `canonical_reads` frontmatter or a sitemap+ontology read in its first step |
| Persona ontology | `scripts/check-persona-ontology.js` | Persona missing required frontmatter, wrong section order, stale include hash, or 7th unsanctioned persona file |
| Skill ontology | `scripts/check-skill-ontology.js` | Skill missing `name`/`description`/`type`, missing `## Contract`/`## Steps`, stale include hash |
| Agent-voice ontology | `scripts/check-fragment-ontology.js` | `config/agent-voice/` missing its base/channel purpose headers, or owner voice (PII) surfacing under shipped config |
| Architecture doc schema | `scripts/check-arch-doc-schema.js` | `product.md`/`architecture.md`/`structure.md` missing required `##` sections |
| Structure check | `scripts/check-structure.js` + `scripts/smart-quarantine.js` | Files outside their declared home — routes them to `quarantine/` |
| Identity chain (unified) | `scripts/check-agent-os.js` | Any dangling/wrong-target/orphan/stray adapter across Claude skills+agents, Codex, Cursor; `agents/dist/` stale vs sources; missing DO-NOT-EDIT headers. `check-identity-dist-fresh.js` and `check-skill-adapters.js` are thin back-compat stubs that delegate here. |

## Change rules

- If product truth changes, update `architecture/product.md` first.
- If architecture changes, update `architecture/architecture.md` and tests or code together.
- If file placement changes, update `config/root-allowlist.lock.json`, `architecture/structure.md`, and the enforcing tests/scripts together, with exact owner-approved touches.
- If files move, regenerate `architecture/sitemap.md` and `architecture/ontology.md`.
- If a doc starts accumulating history instead of decisions, distill it back down.
